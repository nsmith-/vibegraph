# vibegraph v0.2.3

The squared-order and Majorana release. Squared-order constraints and
processes with Majorana fermions or fermion-number violation, refused until
now, run. Two silent wrong answers are fixed: a chirality error on charged
scalars, and Goldstones that some models flag in a spelling vibegraph did not
read. `generate` uses every core, and multijet cards enumerate several times
faster.

## Upgrading

- **Artifacts written by v0.2.2 are refused.** The UFO reader now reads the
  Goldstone flag in every spelling MadGraph accepts, `GoldstoneBoson` included.
  v0.2.2 kept such a model's Goldstones as physical scalars, and its artifacts
  embed the model as v0.2.2 read it, so nothing else in the file can tell. On
  `Bprime_no_b_mass`, `t t~ > z h` integrates to 17.70 pb in v0.2.2 and
  2.527 pb in v0.2.3.

  Diagram and integrate artifacts therefore record a new enumeration version,
  and a v0.2.2 file is refused by name. Enumerate or integrate again from the
  card. Integrate artifacts are now format 25, which records the release that
  wrote them (`writer_version`); v0.2.2 cannot read them.
- **σ moves on the cards named under "Physics fixes".** A result from v0.2.2
  on such a card is wrong; regenerate it.
- **`generate` writes different events for the same grid and seed.** The
  accept/reject pass now runs in parallel on `-j` threads, on random streams
  fixed by the seed alone. A v0.2.2 seed does not reproduce v0.2.2's events,
  at any `-j`. The sample is statistically equivalent to the v0.2.2 one, but
  not the same events. The output no longer depends on `-j`: one seed gives the
  same file at any thread count. Integration's random streams are unchanged:
  on a card no fix below touches, the same card and seed give the same σ.
- **Reweighting is per event helicity by default** (#182).
  - A reweight card with no `change helicity` line now gets MadGraph's
    default: each weight is `|M_hyp(λ)|² / |M_card(λ)|²` in the event's own
    helicity combination. v0.2.2 wrote the helicity-summed ratio.
  - The events and the expected σ are the same; the weights' spread is larger.
  - To get v0.2.2's weights, byte for byte, add `change helicity False` to the
    card or pass `generate --reweight-helicity summed`.
  - The per-event ratio is refused, naming both remedies, for polarized legs,
    a signed squared-order selection, 2 → 1 and 1 → n processes, and events
    with identical outgoing particles under different mothers.
  - A `change helicity` line after the first `launch` is now refused.
- **Some inputs are now refused that were accepted before.**
  - A run-card line that is an unfilled `$` placeholder, such as
    `$DEFAULT_PDF_SETS` from a CMS gridpack template. v0.2.2 skipped the line
    silently, so the run used the field's default (#172).
  - A UFO parameter that reads a name rebound under an `if` whose condition
    the loader cannot evaluate. v0.2.2 silently used the name's earlier value;
    MadGraph uses whichever value the `if` leaves (#201).
  - `generate --parallel-diagrams`, which did nothing there (#185).
- **Some param-card entries are now ignored with a warning instead of
  refused** (#177), as MadGraph ignores them:
  - entries in a block the model does not define;
  - `MASS` and `DECAY` entries, decay tables and `Auto` widths at a code no
    particle has.

  A mistyped `MASS` or `DECAY` code therefore binds with only the warning. An
  ignored decay table is left out of the event file's `<slha>` header, where
  MadGraph copies it. An unknown code inside a block the model defines is still
  refused.
- **`enumerate` writes two more files.** `parameters.json` and
  `param_card.dat` sit beside `diagrams.json`, and none of them is overwritten
  without `--force` (#171).

## Highlights

- **Squared-order constraints** (#168).
  - `NAME^2==n`, `<=`, `=` and `>` select interference terms by coupling
    order, as MadGraph does. So do the `aEW` and `aS` aliases, `WEIGHTED==n`
    and `WEIGHTED>n`.
  - Each amplitude is split by coupling-order class, and only the selected
    class pairs enter |M|².
  - `integrate` reports a signed σ for an interference-only selection.
    `generate` refuses one, because unweighting writes no negative-weight
    events.

  Each class matches MadGraph standalone per helicity and per flow, to 1e-14,
  on two SMEFTsim `e+ e- > t t~` rows (`NP^2==1`, `NP^2==2`) and a QCD
  `u u~ > u u~` row (`QCD^2==2`). σ is checked internally only: SM, the
  interference and |NP|² sum to the unsplit `NP<=1` σ within 8e-6. No MadGraph
  σ is banked yet for a squared-order selection.
- **Majorana fermions and fermion-number violation** (#169).
  - A fermion line with no fermion-number arrow (a Majorana fermion such as a
    neutralino, or an RPV or diquark vertex) gets an orientation, and each
    vertex is read along or against it, as MadGraph does.
  - Every diagram matches MadGraph's `AMP()` per helicity, to 1e-12, on 16
    standalone tables. The tables cover the toy Majorana and diquark models
    and MSSM neutralinos and charginos.
  - One σ is checked: the toy model's `lt~ lt > sc sc~` agrees with MadEvent
    to 0.05% (0.7σ).

  This support is validated on undecayed processes only. Decay chains with a
  Majorana or fermion-number-violating line are refused (see Known issues).
- **`DECAY <pdg> Auto`** binds the tree-level two-body width, computed from the
  model's own vertices (#179).
  - Widths match MadGraph 3.7.1 channel by channel for the SM t, W, Z and H
    and g2HDM's heavy Higgs bosons.
  - A particle with a three-body mode through an off-shell daughter, which
    MadWidth can add, is refused, naming the mode. In the SM, t and W bind; Z
    and H are refused.
- **Per-event-helicity reweighting** (#182), as described under "Upgrading".
  It agrees with MadGraph's reweighting event by event on four rows, one of
  them a decay chain.
- **Multicore `generate`** (#180). Accept/reject runs on every `-j` thread.
  On a 4-core host at `-j 4`:
  - an MLM-matched `p p > e+ e-` + 0–2 jets sample runs 3.4× faster;
  - `p p > t t~` runs 2.2× faster, bound by the serial event-file write.
- **Faster enumeration and compilation** (#185). Enumeration skips flavour
  assignments that break a number every vertex of the model conserves, and
  runs on every core. Each diagram set compiles once, on the pool.
  - On a 4-core host, DY + 0–3 jets enumerates in 4.9 s at `-j 2` (18.4 s
    before).
  - W + 0–4 jets and Z(→νν) + 4 jets enumerate in 261 s and 181 s at `-j 4`.
    Before, one such 4-jet line was projected at about 2900 s.
  - `integrate --check` on `p p > e+ e- j j j` takes 1.4 s (11.4 s before).

  Neither the prune nor the pool changes a diagram set: the sets are byte for
  byte those of the serial walk.
- **Model and provenance reports** (#171).
  - `vibegraph parameters` writes a model's parameters as JSON with a default
    param card. Each parameter carries its class, constraints, reweightability
    and whether it enters the process.
  - `integrate` and `inspect` report the artifact's `format_version`,
    `enumeration_version` and `writer_version`.
  - An artifact refusal carries a machine-readable `reason`.
- **Progress and timing records** under `--output-ldjson` (#183, #186).
  - `integrate` and `generate` write a `phase` record as each phase starts and
    ends, so a run killed at a time cap names its phase.
  - Every `progress` record carries a run-global position (`phase`, `phases`)
    that never goes backwards, and per-group stages name their group.
- **More UFO models load.**
  - Parameters defined under `if configuration.<flag>` blocks, and conditional
    parameter values, are evaluated against `configuration.py`. SMEFTsim's
    `ctGpatched` and `dim6top_LO_UFO` load (#172, #201).
  - A `propagator` given as a list or a dict is read as its unitary-gauge
    entry, as MadGraph reads it (#178).

## Physics fixes

These change results. Each was a silent wrong answer.

- **Charged-scalar chirality** (#169). On a vertex whose particles are not
  their own conjugate set, a bare chiral projector was read with the wrong
  chirality. This mattered where the two chiralities carry different
  couplings, as on charged-Higgs Yukawa vertices. Every diagram now matches
  MadGraph 3.7.1 standalone per helicity, to 2e-15. No Standard-Model vertex
  is affected.
  - **g2HDM charged Higgs** (#174, #203). The +2.4% to +4.4% excess at
    M900–M1750 was this bug. At M1000 the fix lowers σ by 3.0 ± 0.4%.
    - Five seeds now read vg/MG 0.9991 ± 0.0088 (M1000) and
      0.9995 ± 0.0062 (M300).
    - One seed on each of the other masses reads 0.986–1.016.
  - **MSSM `t t~ > H+ H-`**: v0.2.2 got the bottom-exchange diagram wrong. At
    √s = 1 TeV with fixed beams, σ moves from 1.0151 fb to 0.7558 fb.
  - **VLQ `T' t H` interference** (#208). A build without the fix gets the
    five `VLQ=2` diagrams of `g u > h t b~ d` wrong, and with them the
    interference sign. v0.2.2 is such a build.
- **Goldstones flagged `GoldstoneBoson` were kept** (#178, #177). Some
  FeynRules exports spell the flag that way. vibegraph read only
  `goldstoneboson` and `goldstone`, so those models' Goldstones entered the
  diagrams as physical scalars.
  - Bprime cards 156, 877 and 878 go from 396 diagrams to 198.
  - bstar_tW (card 157), which v0.2.2 refused for too few effective points,
    integrates: vg/MG 1.0069 ± 0.0075 over 20 seeds.
  - Those three Bprime cards read vg/MG 0.9925, 1.0023 and 0.9886 over 20
    seeds.
  - MSSM_SLHA2, NMSSMHET and loop_sm_twoscalar spell the flag the same way.
    The campaign's 49 released cards on them have the same diagram sets as
    in v0.2.2.
- **Multichannel missed a collinear region** (#184). On TprimeBToTZ M1800
  (card 126), four of five seeds read about 3% low. They missed `g → b b̄` with
  the b̄ collinear, which a channel's transfer bound cut out although the b̄
  carries no pT cut. Each bound is now held to what a cut on that side
  proves. Twenty seeds read vg/MG 1.0026 against same-scheme MadGraph 3.7.1.
  `p p > t t~ j` moves within its error.

## Other fixes

- **Resonance records in mixed flavour groups** (#188). `generate` refused a
  flavour group whose members carry an s-channel line of different flavours.
  Each member's resonance code and colour now come from its own diagrams, as
  in MadEvent. An event whose subprocess has no code for a resonance is written
  without intermediates, and a warning counts such events.
- **A zero matrix element names its cause** (#177). When |M|² is zero on every
  point that passes the cuts, the refusal lists the vertices whose couplings
  all evaluate to zero. On the TpTp cards it names `KS10D(3,3) = 0` in the
  gridpack's own param card, which MadGraph shares.
- **A decay-chain stitching assertion is a named refusal** (#177). No known
  card reaches it.

## Known issues

### Registered deviations from MadGraph
New:
- **MadGraph 2.9.18 on the DY1j `ptj1` bins.** MadGraph 3.7.1 agrees with
  vibegraph to 0.16% or better in all four bins. 2.9.18, which made the CMS
  gridpacks, reads 3–8% low at 100–600 GeV and 1.4% high above 600 GeV. v0.2.2
  was right on these cards.
- **MadGraph 2.9.18 and 3.5.7 under-sample the VBS stable-boson cards** (#170).
  Their matrix elements agree with vibegraph per flow and per helicity on all
  five cards. What is left over MadGraph 3.7.1 is MadEvent's default-survey
  bias. Card 700 reads 0.9997 ± 0.0017 against 3.7.1 with its iterations
  re-combined with equal weights. The same bias is the +2.7% on WBQ card 260.

Unchanged from v0.2.2:
- identical particles across decays;
- widths below 1e-6 of the mass.

### Open
- **Majorana and fermion-number-violating decay chains are refused.** The
  support above is validated on undecayed processes only. A decay chain whose
  diagrams carry a Majorana fermion or a fermion-number-violating vertex is
  refused at enumerate, even when the stitched line is a boson. That refusal
  covers all 38 CMS target cards for this support: the 7 HNL cards and the 31
  TypeIII, leptoquark, suu and VLQ → ττ cards it was aimed at. All of them are
  decay chains.
- **The complex-mass scheme is refused** (`set complex_mass_scheme`). 14 CMS
  VLQ gridpacks set it.
  - On pair production the scheme is small where it was measured. MadGraph
    3.7.1 puts its effect on TprimeBToTZ card 126 at −0.04%. Cards 615–618,
    run without it, read 0.987–1.012 against their complex-mass references.
  - The five TprimeBToTH interference cards built with it (`VLQ^2==2`: 124,
    125, 610, 612, 614) are not comparable to their references. Their σ is a
    cancellation, and near the T' pole the scheme rotates the propagator's
    phase. MadGraph 3.7.1 with the scheme on against off reads 1.23× on card
    612 and 1.74× on card 614.
  - In the real-mass scheme vibegraph agrees with MadGraph on those two cards:
    0.986 ± 0.019 and 0.982 ± 0.044.
- **Signed squared-order selections do not generate.** `generate` refuses
  them, since unweighting writes no negative-weight events. Their σ from
  `integrate` is complete.
- **An amplitude-order `==` or `>` does not set the squared order MadGraph
  implies.** On a card with no run card, `p p > t t~ QED==0` therefore misses
  MadGraph's interference defaults (`use_syst`, `dynamical_scale_choice`,
  `sde_strategy`). This is a silent difference on default run cards.
- **`dim6top_LO_UFO` loads, but no amplitude or σ is checked against
  MadGraph.**
- **Two UFO forms are silently misread:**
  - a `propagator` dict without key 0 reads as no propagator, where MadGraph
    fails;
  - a `Parameter` defined under `for`, `while`, `with` or `try` in
    `parameters.py` is neither loaded nor refused. v0.2.2 did the same.
- **VBS cards 134 and 967 read about 0.5% above MadGraph** even at
  `hard_survey = 2` with equal weighting. This is unattributed.
- **The VLQ interference σ on cards 612 and 614 dips at 4× budget** and
  returns at 8×. Few-seed spreads understate its scatter.
- **`ee_to_wpwm`'s angular shape** disagrees with MadGraph's banked sample on
  most seeds; σ agrees. Its KS columns are informational.
- **Enumerating the VBS ssWW card (703) takes 65 minutes**, then is killed
  for memory (at 4.2 GB or more) in teardown. It writes its artifact but no
  result record.
- **A card with σ = 0 at LO** still runs to the point cap before it refuses.
  This is a time cost only.
- **Unattributed small offsets** (unchanged):
  - `p p > w+ h01` (HToAATo4B) reads about 0.1% high against MadGraph;
  - ZPrimeToTT's quoted error is below its seed spread.
- **`time_of_flight ≥ 0`** is refused. It changes only the event record, not
  σ.

### Not supported (refused by name)
- **Gluino pairs.** A vertex joining two identical Majoranas through a
  structure that is not its own charge conjugate is refused (`p p > go go` in
  MSSM_SLHA2).
- **Majorana or fermion-number-violating pairs on a vertex of more than two
  fermions.**
- **A squared-order constraint on a decay-chain line**, which MadGraph refuses
  too, and **a negative squared-order value under `==` or `>`**.
- **`Auto` widths** beyond two bodies, and `Auto` in a restriction card. Give
  `DECAY <pdg> Auto` in the param card instead.
- **Unchanged from v0.2.2:**
  - restriction cards that omit an external parameter;
  - fixed-energy 2 → 1;
  - beams other than unpolarized proton–proton or fixed-energy partons;
  - beam polarization;
  - CKKW-L;
  - photon isolation;
  - NLO;
  - an `xqcut` card with `auto_ptj_mjj = F` and no `mmjj` or `drjj`.
