# vibegraph v0.2.2

The SMEFT release. SMEFTsim v3 and v2, and the CMS model store's SMEFT
family, now load and generate the full |M|². The largest refusal classes from
the model-store scan and the v0.2.1 gridpack campaign are closed. This release
also fixes a factor-of-four σ on repeated decays and the MLM matching panic,
and makes `integrate` safe to run under a batch system.

## Upgrading

- **Artifacts written by v0.2.1 are refused.** Enumeration output changed:
  - coupling orders are now spent vertex by vertex, as MadGraph spends them;
  - repeated identical decays are stitched once.

  Diagram and integrate artifacts therefore record a new enumeration version,
  and a v0.2.1 file is refused by name. Integrate again from the card.
- **σ moves on the cards named under "Physics fixes".** A result from v0.2.1
  on such a card is wrong; regenerate it.
- **Some run-card values are now refused that were accepted before.**
  - `misset < 0` is refused by name where it would bind, which is any card
    with no lepton cut of at least 1 GeV.
  - A fixed-beam card whose scale fails at a sampled point is refused by name
    instead of panicking.

## Highlights

- **SMEFT models load.**
  - UFO coupling orders may be negative, such as SMEFTsim's `QED:-1` vev
    insertion. They are spent vertex by vertex, as MadGraph spends them
    (#141).
  - Restriction cards are applied as MadGraph applies them: `9.999999e-1` is
    one, `0.000001e-99` is zero, and `-full` loads unrestricted (#144).
  - The UFO loader accepts these value forms (#145):
    - parameter value expressions and bare names;
    - vertex coupling lists, each member filed by its own order;
    - particle attributes that reference parameters;
    - models with no `coupling_orders.py`.

  SMEFT_alpha matches MadGraph per diagram and per helicity.
- **`import model` options** such as `--modelname` are honoured (#145).
- **One-body final states.** `p p > z` and other 2 → 1 processes at proton
  beams integrate, and match MadGraph (#142).
- **The coloured-scalar seagull.** Squark pair production compiles its
  squark–squark–gluon–gluon contact. The 0-jet SMS-StopStop σ agrees with
  MadEvent to 0.01% (#146).
- **Mixed outgoing masses.** Flavour groups split by outgoing masses slot by
  slot, as MadGraph's `find_process_classes` does, so ZPrimeToTT integrates
  (#147).
- **Rank cuts.** `ptj1min`–`ptj4max` and `ptl1min`–`ptl4max` are implemented
  as MadGraph's `cuts.f` rank cuts. The CMS ZH SMEFTsim_topU3l cards integrate
  at their real `ptl1min` (#152).
- **Run-card reporting.**
  - Off sentinels (`-1`, `0`, `≥ ebeam1 + ebeam2`) are read as MadGraph reads
    them.
  - `vibegraph run-card` prints the resolved card.
  - A generated per-release table classifies every run-card field.

  (#152)
- **Batch-safe `integrate`** (#143):
  - SIGTERM is a stop request;
  - the result records a `stop_reason`;
  - `integrate --check` stops before sampling;
  - `generate` output is written atomically and compressed by its extension;
  - `enumerate` reports progress with a total;
  - the default thread count reads the affinity mask, the cgroup quota and
    `OMP_NUM_THREADS`.

## Physics fixes

These change results. Each was a silent wrong answer.

- **Repeated identical decays read 4× high.** When two identical decays sit on
  a vertex's interchangeable slots, such as
  `h01 > a01 a01, a01 > b b~, a01 > b b~`, stitching kept every diagram twice,
  so |M|² was exactly 4× at every point. The four CMS HToAATo4B cards were
  affected. σ now agrees with MadGraph at two masses (#150).
- **An unreadable optional UFO file read as absent.** For SMEFTsim that
  silently replaced the model's own `sec` and `csc` with the generic complex
  definitions. Such a file is now refused by name (#157).

## Panics fixed

- **MLM-matched reweighting on the g2HDM charged-Higgs cards** panicked
  (#153).
  - The cause: flavour grouping joined subprocesses whose matrix element
    vanishes at the card with live ones.
  - MadEvent never reaches that merge.
  - Vanishing groups are no longer clustered, and any remaining fault at a
    sampled point is a named refusal.
- **At fixed beam energy, a scale that failed at a sampled point** panicked. It
  is now a named refusal (#156).

## Other fixes

- **Memory.** `integrate` memory grew by about 400 MiB per iteration on
  multijet MLM cards (GJ-4Jets: 23.9 GB by iteration 45). It is now flat
  (#155).
- **Partial event files.** A `generate` run refused for a sampled-point fault
  no longer leaves an event file under its final name (#159).

## Known issues

### Registered deviations from MadGraph
Unchanged from v0.2.1:
- identical particles across decays;
- widths below 1e-6 of the mass.

### Open
- **Squared-order constraints** (`QED^2<=…`) are refused. They are planned for
  v0.2.3, so SMEFT samples in this release are full |M|² only.
- **`dim6top_LO_UFO`** is refused at its configuration-dependent parameter
  definitions.
- **A card with σ = 0 at LO** runs to the point cap before it refuses. This is
  a time cost only.
- **Unattributed small offsets:**
  - `p p > w+ h01` (HToAATo4B) reads about 0.1% high against MadGraph;
  - ZPrimeToTT's quoted error is below its seed spread.
- **One unexplained rank-cut row.** CMS `DY1jToLL_M-1to10_Pt-100to200`
  (`ptj1min = 100`, `ptj1max = 200`) reads 2.7% above the gridpack's MadGraph
  σ on one seed. Its neighbouring bins agree to 0.2–0.3%. This is under
  investigation.
- **g2HDM MLM cards no longer panic, but their σ is unmeasured.** One seed
  takes hours, so it moves to the post-release campaign.
- **`time_of_flight ≥ 0`** is refused. It changes only the event record, not
  σ.
- **v0.2.1's open measurements stand.**

### Not supported (refused by name)
- **Restriction cards that omit an external parameter.** MadGraph refuses them
  too.
- **Fixed-energy 2 → 1.** MadGraph returns zero for it.
- **Unchanged from v0.2.1:**
  - Majorana fermions;
  - beams other than unpolarized proton–proton or fixed-energy partons;
  - beam polarization;
  - CKKW-L;
  - photon isolation;
  - NLO;
  - an `xqcut` card with `auto_ptj_mjj = F` and no `mmjj` or `drjj`.
