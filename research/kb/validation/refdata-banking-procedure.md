# Banking and publishing a refdata bundle

A new [reference bundle](refdata-bundle.md) is cut when a sprint banks MadGraph
runs a gate needs on disk. It runs in three phases, in order: a close-out in the
development container (run the whole banked layer, register every new row and
cell, wire the generators), the bank, on the host that holds the full MadGraph
work area, and a re-verification from the published bundle on a machine that has
never generated a run. The sprint closes when the last is green. The generator
commands themselves are described in
[tooling/madgraph-reference-generation](../tooling/madgraph-reference-generation.md),
and how a run is made and read in
[madgraph-reference-runs](madgraph-reference-runs.md).

## 0. Classify every artifact

Each artifact falls in one class, and the class decides what the bank does with
it[^n41-z]:

| class | examples | at the bank | reproduction check |
|---|---|---|---|
| inputs | `.mg5` scripts, run cards, patches, reproducers | committed; not references | — |
| committed structural tables | censuses, `diagrams.json`, `configs.json`, `interactions.json`, `mlm_census.json` | regenerated by `refs` (or the stage that owns them) | must match exactly, except where noted below |
| committed numeric tables | amplitude and standalone per-flow tables, decay amplitudes | regenerated | at the rounding scale |
| committed MadEvent σ scalars | `mlm_sigma_reference.json`, `grammar_sigma_reference.json`, decay and on-shell-veto tables | re-measured | every value within its seed error; never pinned to bits |
| runs a gate needs on disk | `output/<row>` event files, banners, logs, `leshouche.inc`, `matrix*_orig.f` | banked | gated on the host |
| regenerated, not banked | kT and MLM dumps, full process directories, shared-seed work areas | regenerated by their stage | their gates run on the host |

Decay widths, decay-chain σ and decay-chain events are committed summaries
written by `gen_decay_widths.sh` and `gen_decay_chain_events.sh`, so their gates
run on any checkout. They are deliberately not `[[process]]` rows: as rows, their
runs would land in `output/`, where `validate_scales` asserts an inventory and the
extractors and colour oracle would pick them up with no plan for a decay or a
chain[^n38-z1].

## 1. The bank host

- A checkout at the close-out commit.
- The submodule **checked out** at its pin, run through `mg5_pinned.sh`. A copy
  without `.git` works but prints a "development version" banner into proc cards
  ([madgraph-oracle-pinning](madgraph-oracle-pinning.md)).
- The pixi `madgraph` environment with gfortran and LHAPDF, and both PDF sets
  fetched; the `pythia` environment for an optional Pythia step.
- Disk for the new process directories, replays and dumps.

## 2. Start from the current bank

`pixi run fetch-refdata` unpacks the pinned bundle into
`validation/madgraph/output/`; a work area that already holds process directories
is left alone, as the oracle layer's cache. The `refs` stage needs files the bundle
trims from process directories (`coloramps.inc` and the rest of a buildable
`SubProcesses`), so it cannot run on a work area unpacked from the bundle alone:
fill them in from a full work area without overwriting (`cp -Rcn`)[^n41-z].

## 3. Generate

`pixi run -e madgraph generate-references <stages>` (for example `deps madgraph
seeds mlm refs`). Generators are cached: an existing process directory is not
regenerated, a finished seed whose run card is byte-identical is read back from
its `vg_seed_result.txt`, `VG_FORCE=1` re-runs, and `ROWS=` / `SEEDS=` narrow a
run while keeping the committed rows it did not touch. A stage may rebuild a run
whose work area is not banked; restore that run's bundled bytes before assembling
if its banners or logs changed.

## 4. Check reproduction before bundling

`git diff --stat validation/`, then each file, against the class table. Compare
**findings, not bytes**, wherever MadEvent itself is not bit-reproducible:
- **Multi-group unweighting** (`pp_to_jj`'s five subprocess directories) is
  scheduling-sensitive: a re-run yields a different, equally valid sample. Never
  regenerate such a run to reproduce the bundle; compare it by
  distribution[^n28-c5][^n28-z7].
- **Across hosts**, `pp_to_ll_0j2j_mlm` and `pp_to_ttx_0j1j_mlm` are not
  bit-equal, so `mlm_census.json`'s event counts and `mlm_dump_manifest.json` move
  too. Check that the census's findings hold (no mixed jet-ness, each channel's
  memo single-valued) and commit the regenerated manifest so it pins the dumps the
  host gated.
- Single-group MadEvent seeds have been bit-equal across a Linux container and a
  macOS host (176 seeds over 40 rows)[^n38-b1]; that is an observation, not
  something the check relies on.

A structural difference, or a scalar outside its seed error, is a finding: stop
and report it, do not overwrite.

## 5. Gate on the host

`pixi run --skip-deps validate` against the work area, so every new row's gate
meets its fresh run before the bundle is frozen; a bare `pixi run validate` would
regenerate. Then run the oracle-layer gates the new rows have, recording each
command with its output. Gates that sweep the work area meet every new run, which
is where an undeclared row first fails.

## 6. Assemble

Set `[refdata] version` and `archive` first, then `bash
validation/madgraph/assemble_bundle.sh`; it reports the hash it made. Check:
- two assemblies are byte-identical;
- the member list is the previous cut's, each member byte-identical, plus the new
  rows (or, for a re-card, the same list name for name);
- every run's decompressed event text has the same sha256 through pack and
  unpack (the unpack re-gzips, so compressed bytes differ by design).

## 7. Prove a clean export

A `git archive` export of the tree, given only the pinned submodule content, the
two fetched PDF sets and the bundle, runs `pixi run --skip-deps validate` green
and renders a report byte-identical to the work area's. `git archive` emits an
empty directory for a submodule gitlink, so copy the submodule's contents into it
(`cp -R …/mg5amcnlo/. "$EXPORT/research/refs/mg5amcnlo/"`), not the directory
itself.

## 8. Publish and flip the pin

Publish the archive as the release asset of tag `refdata-<n>` and check the
downloaded asset hashes to the pin. Update `[refdata]` (`version`, `archive`,
`url`, `sha256`, `size_bytes`) with a comment line for the cut; drop
`bundled = false` and `status = "planned"` on the rows it now carries. Commit
with the host, the MadGraph version and the wall time in the message body. If any
pixi environment changed, check `pixi.lock` with a locked install: a close-out
once tripped CI on exactly that. Until the asset exists the pinned `url` 404s and
CI's banked job is red; `$VIBEGRAPH_REFDATA_SOURCE` is the only route to the
bytes[^n28-z7].

## 9. Re-verify from the published bundle

On a machine that has never generated a run (the container with
`validation/madgraph/output` removed, or CI): `pixi run fetch-refdata` verifies the
hash and `pixi run validate` passes. Only then, and only where agreement is a
recorded measurement from this run (or from the bank host's run, for oracle-layer
cells whose inputs are not in the bundle), move cells from `info` or `uncovered`
to `gate`[^n38-73].

## Caveats

- **The member list is the contract.** A gate that reads a work-area file the
  bundle does not list passes on the bank host and fails on every fetching
  checkout. Either the file joins the bundle (a re-cut) or what the gate needs is
  extracted into a committed reference (as `configs.json` was for the channel
  counts) ([refdata-bundle](refdata-bundle.md)).
- **First runs on a new host find generator bugs.** macOS's first bank found four
  that a Linux dry run could not: BSD `seq` printing seeds as `2.02609e+07` (which
  collapsed every row onto one cached run), `sed -i` with no suffix, a missing
  `-lc++` on Darwin, and SMEFTsim's Python 2 UFO needing MadGraph's own
  `convert model`. A later bank found that the amplitude generator emitted a row
  whose probe module was never built. Treat such failures as generator findings
  and fix them in the generator.
- Load can kill a full banked run on a shared host (one aborted under a load
  average of about 115 on 16 cores and passed alone); re-run the failing target
  alone before treating it as a regression.
