# References come from pinned MadGraph 3.7.1 with LHAPDF PDF sets

## The decision

Every MadGraph reference run is generated by the pinned submodule
`research/refs/mg5amcnlo` at `b7687064` (MadGraph 3.7.1), invoked through
`validation/madgraph/mg5_pinned.sh` under `pixi run -e madgraph`. The packaged
`mg5amcnlo = 3.5.7` in the pixi `madgraph` environment supplies only the
toolchain: the Python 3.11 with `six` the submodule needs to generate, and the
gfortran and LHAPDF that `madevent` needs to build and run. It is never invoked
for a reference[^n27-dec].

Every hadron-beam reference uses `pdlabel = lhapdf`, at `lhaid = 247000`
(`NNPDF23_lo_as_0130_qed`, the [pinned PDF set](../scales-pdf/pinned-pdf-set.md)),
never MadGraph's internal `nn23lo1`[^n29-g].

## Why 3.7.1

- The 3.5.x line's `sde_strategy = 2` channel weight is dimensionally wrong and
  never peaks on a resonance; the fix (3.6.2) was never backported, so no 3.5.x
  run can be a narrow-resonance reference
  ([madgraph-defects](madgraph-defects.md)). Banking on a known-defective version
  would build every later bundle on it.
- 3.5.7 also applied the `nn23lo1` set's `αs(M_Z) = 0.130` to fixed-energy runs
  whose beams carry no PDF, which changes what a partonic σ means
  ([refdata-sigma-comparability](refdata-sigma-comparability.md)).
- The packaged 3.5.7 `mg5_aMC` crashed in `generate_events` on linux-64
  (2026-09-25).

The six 3.5.7 runs still in the bundle (`ee_to_mumu_tata_qcd0`'s window,
anti-window and `control_2026080{1,2,3}` runs and `var_sde1`) are deliberate:
they are the evidence for the 3.5.x defect and stay at the version they measure.

## Why LHAPDF only

`nn23lo1` is MadGraph's internal parton-density parameterisation, not an LHAPDF6
grid this crate's `pdf/` layer can load. A cross section built here against an
`nn23lo1` run would convolve different densities and measure that difference.
There is no oracle for the parameterisation in this tree, and implementing it
blind was declined[^n28-z4].

The attribution was checkable rather than argued: each process blocked on
`nn23lo1` had a twin carded onto `lhaid = 247000`, and every twin gated. The four
`nn23lo1` runs (`pp_to_bb`, `pp_to_bb_qcd2`, `pp_to_llj`, `pp_to_ll_scalefact2`)
were re-carded and **replaced**, not added: the bundle kept the same member list
name for name, and the superseded runs went to a local retired area off the
bundle[^n29-g].

The re-card changes the beams, so σ moves across the boundary (MadGraph's own
`Integrated weight`)[^n29-g1]:

| run | `nn23lo1` | `lhaid 247000` | shift |
|---|---|---|---|
| `pp_to_bb` | 417 202 400.0 | 376 243 100.0 | −9.8% |
| `pp_to_bb_qcd2` | 417 208 048.74 | 376 246 848.68 | −9.8% |
| `pp_to_llj` | 503.5553 | 504.6288 | +0.21% |
| `pp_to_ll_scalefact2` | 1958.82 | 1958.95 | +0.0066% |

Read the PDF a run actually used from its event file's `<init>`
(`PDFSUP1 = PDFSUP2 = 247000`), not only from the card. The second fetched set,
`NNPDF31_lo_as_0130`, serves only the multi-subgrid PDF-grid oracle, not a
MadGraph reference.

`lpp = 0` rows keep the default `pdlabel = nn23lo1` in their cards; their beams
carry no PDF, and under 3.7.1 their `αs` is the model's own.

## Consequences

- **`mg5_pinned.sh` does the environment work** so callers do not: it runs
  MadGraph in a temporary directory (MadGraph drops a scratch `py.py` in its
  working directory), puts `validation/pdf/` first on `LHAPDF_DATA_PATH` so
  `lhaid 247000` resolves to the pinned set rather than a download, and turns off
  the browser and desktop notifications the pinned checkout (which has no site
  configuration) defaults on. Those settings stay out of the generated
  `Cards/me5_configuration.txt`, so a caller that runs `generate_events` silences
  that file separately (`silence_madgraph_ui` in `gen_hadronic_sigma.sh`).
  `VG_MG5_ROOT` runs a patched copy of the tree instead, which is how a reference
  that needs a MadGraph patch is made without touching the checkout the
  source-reading gates parse[^mg5-pinned].
- **Verify the version in the produced banner**: `VERSION 3.7.1` in
  `Events/*/run_*_tag_1_banner.txt`. A submodule copied without its `.git` prints
  "UNKNOWN DEVELOPMENT VERSION" in proc cards (and ANSI escapes in the LHE banner,
  which `build.sh` strips) even though every source file matches the pin; a bank
  host should check the submodule out rather than copy it.
- **A re-card trips the α_s classification, by design.** `pdlabel = lhapdf` makes
  MadGraph link the grid's α_s, so a re-carded run moves into
  `GRID_ALPHA_S_RUNS` (in both `validate_alphas.rs` and `validate_scales.rs`).
  `resolve()` asserts the source arm both ways, and
  `banked_run_logs_pin_the_alpha_s_source_rule` checks the list against each
  run's own MadGraph log, so a run that changed source fails rather than being
  reclassified quietly[^n29-g6].
- **The negative control survives re-cards**:
  `the_grid_runs_need_the_grids_alpha_s_and_not_the_parameter_cards` intersects
  the grid runs with the fixed-scale runs and asserts that set non-empty on its
  own account.
- **A σ cell that flips after a re-card is read on a budget ladder, not one
  seed.** After the re-card `pp_to_llj` approached the reference from below with
  budget (−2.07% at 75k points an iteration to +0.02% at 600k) and gates at the
  600k rung; the other three were flat and gate at 300k[^n29-g10]. See
  [seed-sweeps-and-budget-ladders](seed-sweeps-and-budget-ladders.md).

Running MadGraph here, the environment and the submodule are described in
[the toolchain concept](../tooling/madgraph-toolchain.md); how runs are made and
read is [madgraph-reference-runs](madgraph-reference-runs.md).
