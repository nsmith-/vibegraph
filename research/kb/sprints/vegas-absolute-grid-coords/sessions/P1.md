## Scope

The two design changes the item names, with no behaviour change:

1. **Invert the VEGAS↔channel contract.** The channel drives the grid one
   coordinate at a time (asks the grid for each invariant's coordinate as it
   builds the point), instead of receiving a pre-drawn vector. The eager path
   stays bit-identical: same draws, same order, same weights.
2. **Every analytic map becomes a fixed transform** with the point's window
   inverted through it, so the mixture density stays grid-free. Today's
   window-relative behaviour must be reproduced exactly by that form.

Do not add `--map-grid-coords` or any absolute-coordinate mode yet; that is P2.
Leave a short design note in your report on how P2 plugs absolute coordinates
in. Include how #48's bin-width bound, which is measured in uniform grid widths,
reads on an absolute axis where the window covers only part of `[0, 1]`.
