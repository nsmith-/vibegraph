Item: `triple-gluon-sign-calibrated-not-derived` (closed by PR #39).
Background: the [B′ report](B-report.md) (the GF(2) solve, its blind spots, and
the mutation table that names the rows pinning the constant). Method:
[bit-exact amplitude debugging](../../../validation/bit-exact-amplitude-debugging.md).

The user decided (2026-10-16) that this sign must be derived, not accepted as
calibrated. `triple_gluon_sign` (`helas/eval/root_diagram.rs`) multiplies every
diagram by −1 per coloured Yang–Mills VVV vertex. B′ found it as the one constant
the GF(2) solve leaves free. Its doc says the sign "belongs to the colour-ordered
decomposition of its antisymmetric `f^{abc}`", but nobody traced that.
`f_to_traces` (`helas/color/tensor.rs`) matches MadGraph's
`f = −2i Tr(abc) + 2i Tr(cba)` term for term, so the sign enters somewhere else.

Find where it enters, and state it as a convention.

1. **Trace one diagram by hand and by machine.** Use the s-channel gluon diagram
   of `u u~ > g g` and its t-channel quark-exchange partner. Follow the colour
   factor and the Lorentz/coupling factor separately, through:
   - the order in which the UFO vertex's `f(a,b,c)` colour indices meet its
     Lorentz slots (`VVV1`'s argument order, the coupling `GC_10`'s sign);
   - how `colorize` assigns those indices to the rooted vertex's legs, and to the
     flow basis;
   - ALOHA's / MadGraph's own colour decomposition of the same diagram (its
     `JAMP()` coefficients for the diagram, from `matrix.f`'s colour data or a
     standalone dump).

   Dump the per-diagram, per-flow complex values on both sides, with the
   −1 removed, and find the one factor that differs: colour, Lorentz or coupling.
2. **State the convention**, and either:
   - move the −1 to the factor it belongs to, if that is where the code reads
     that convention (colour slot order, vertex leg order, …); or
   - keep the constant and replace its doc with the derivation, naming the
     convention it compensates.

   **If the derivation disagrees with the calibrated constant** (a different
   factor, a dependence on something other than the count of triple-gluon
   vertices, or any row it would change), **stop and report before changing
   code.**
3. **Falsifiers.** Add a test that fails if the constant is flipped, and one
   that fails if the sign is attributed to the wrong factor. For example, pin
   the colour factor and the Lorentz factor of the traced diagram separately
   against their derived values, so a −1 moved between them is seen. Run each
   mutation and quote the failing output. State each new test's blind spot.

Gates: `cargo test --workspace`, fmt and clippy;
`cargo test -p vibegraph-lib --test standalone_jamps --test amplitude_oracle`
with every row agreeing. Use the `extended-validation` skill if production code
