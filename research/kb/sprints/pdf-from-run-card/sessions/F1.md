3. **What integrate records** (§1, §3a central entry).
   - Hash, with SHA-256 (C1), exactly the bytes the loader parsed: `.info`
     first, then the member's `.dat`, from one read per file.
   - Make the `.dat` parser take a `&str` / byte buffer.
4. **Lookup** (§5). `vibegraph-lib::cache` resolves a set directory and an
   index through these tiers:
   1. `$LHAPDF_DATA_PATH` (H1 already has this tier);
   2. CVMFS `lhapdfsets/current`, skipping `@DEPRECATED`, `@UNVALIDATED` and
      `.tar.gz` twins;
   3. the cache, where a pinned set must match its pin and an unpinned set's
      sidecar marks a complete publish;
   4. an HTTPS download through an injected fetch-factory callback.

   **Network consent stays structural.** Only the CLI's callback calls
   `network::confirm` and builds `HttpFetch`.
   - Index fall-through (C6): an lhaid missing from one tier's index tries the
     next tier, and last a consented fetch of the current index into the cache.
   - Unpinned prompts carry no size or SHA-256 (C10); `network::Download`
     makes both optional.
   - Tests use the injected callback with an in-memory `MapFetch`. Cover every
     tier and every refusal, with no socket and no `VIBEGRAPH_FETCH_CONSENT`
     (C12).
5. **What `generate` checks** (§3). It loads the recorded set and member and
   refuses when any recorded file's SHA-256 differs (C9). The refusal names
   the file and both digests.
