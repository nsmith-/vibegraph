## Scope

1. In `vibegraph-lib`, `vibegraph-cli` and `validation-report`, demote each
   `pub` item (fn, type, field, method, const, module) that nothing outside
   its crate names, to `pub(crate)` or narrower. An outside user is another
   workspace crate, an integration test, a bench or a `bin/` target, under
   `--all-targets --all-features`.
   - Method is your choice. Suggested: a candidate list by `grep` over the
     other targets, then demote in module-sized batches and let the compiler
     confirm each. Rustc's `unreachable_pub` lint is a helper, not the oracle.
     The batches are deterministic bulk work and may go to narrow sub-agents,
     but you check their output.
   - Re-exports and `pub use` count as uses only if something outside uses
     the re-exported path.
2. Where the demotion makes an item dead (`dead_code` fires), delete it when
   nothing references it and no doc gives it a planned use. Otherwise
   `#[allow(dead_code)]` it with no comment and list it under Found.
3. Close **dead-types-with-stale-docs**: `Applicability::ProtonBeams`,
   `Intertwiner2Leg/3Leg/4Leg`, `Vertex3`/`GaugeVertex`, each deleted or
   given its user, and no doc citing `WeylBasis`, `MinkowskiRep` or a
   fixed-energy `pdlabel` card as a reason for a type.
4. **Don't touch** anything else: no renames, moves, doc rewrites beyond the
   item, or refactors. Other cleanup goes to Found.

## Worktree & long-command discipline


- **First action**: `cd` to the absolute worktree path in your assignment, then
  verify `git rev-parse --show-toplevel` and `git branch --show-current`. If you
  find yourself in the shared main checkout, STOP and report — never edit it.
  Re-verify `pwd` after any resume; resume is when isolation leaks.
- **Background anything expected to exceed ~2 minutes**
  (`run_in_background: true`, output redirected to a log file prefixed with your
  worktree/session name — parallel siblings share one scratchpad and have
  clobbered each other's unprefixed logs). A backgrounded command notifies on
  exit: never spawn sleep-based watcher shells (they compound into
  self-sustaining wake-up rings); draft your notes and report between completion
  notifications instead of idle-waiting. On resume after a stall, first check
  whether the interrupted command finished (`ps`, result artifacts) before
  re-running it.
- **`git status` can hang for minutes** in a worktree full of untracked build
  data; spot-check with `git log` / `git diff --stat` instead.
- **Run gates with `--skip-deps`** unless the assignment explicitly says
  reference data must be regenerated — without the reference data present, a
  bare `pixi run validate` silently launches a multi-hour MG regeneration.
