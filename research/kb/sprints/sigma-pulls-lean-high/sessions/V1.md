## The question

The first banked run on refdata-10 put 47 σ pulls at mean +0.65, spread 0.87
(about 5 standard errors from zero). No single pull is evidence; the
population is. Is the lean the reference's (MadEvent's mean²/variance
iteration combination reads σ low) or this side's?

## Scope

1. **This side, on the current commit.** Run the σ gates that read seeded
   records (`validate_sigma`, and the hadronic/MLM σ gates that read refdata-10
   records; find them by their reader) and record per row: this side's value
   and error, the record's reported seed mean and error, and the pull. Confirm
   you reproduce the 47-row population (mean, spread) before going further; if
   you do not, stop and report why. Detach the run.
2. **Three re-reads of the same population**, each a recorded table:
   - against each record's **equal-weight** seed mean (with the same
     max(quoted, spread/√n) error rule), noting rows whose equal-weight values
     are heavy-tailed (report a median/trimmed variant beside the mean where
     they are);
   - against the record's **4× seeds** (the budget screen): if the lean is
     MadEvent's adaptation bias it should shrink at 4×; say what two 4× seeds
     can and cannot show;
   - **relative units**: the mean of rel offsets weighted and unweighted, so a
     lean carried by underestimated reference errors is told apart from a
     shift of σ.
3. **Split the population** by row class (fixed-beam ee/uux/gg, toy/SMEFT,
   hadronic, grammar, MLM) and by the record's (equal-weight − reported)
   difference: does the lean track that difference row by row?
4. **This side's own share.** The pulls are one fixed seed per row. For a
   handful of rows that carry most of the lean, run this side over ≥5 seeds
   (unweighted mean, spread, χ²/dof) to separate a this-side offset from a
   lucky draw. Keep the total compute under ~2 h on this host; say what you
   left out.
5. **Attribute**, with what would falsify it. If the lean survives the
   equal-weight re-read, name the 2–3 rows where an adaptation-free estimate
   (as PR #26 built for `ee_to_mumua`) would decide it and estimate its cost;
   do not build it. If the reader should change (e.g. equal-weight on more
   rows), write the proposal and its evidence for the manager: that is a design
   decision for the user.

Commit the analysis as a reusable tool (an `#[ignore]`d probe beside the σ
gate's reader, or a `seed-record` subcommand — your choice, say why) so the
population table can be regenerated on a later commit. Hermetic tests and
`cargo clippy --workspace --all-targets -- -D warnings` must pass.
