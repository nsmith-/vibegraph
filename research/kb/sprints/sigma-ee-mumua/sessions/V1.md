## Scope

1. **The named probe:** the 2D cell `[39.4, 77) × [86, 96)` in
   `(pt(γ), m(μμ))`, integrated directly on both sides (MadEvent as a
   diagnostic run with the cell imposed as cuts, ≥5 fresh directories; this
   side ≥5 seeds). Then the neighbouring cells needed to tell
   "our `η(γ)` at fixed `m(μμ)` differs" from "MadGraph's
   `pt(γ)`-restricted runs under-recover".
2. **An adaptation-free estimate** of `[39.4, 77)` (and `[77, 144)` if
   affordable): plain non-adaptive sampling whose error is honest, as a
   third opinion independent of both integrators' grids.
3. **Attribute**, with what would falsify it.

**Watch item (from `sigma-2to4-offset`, manager-checked):** on a fixed-beam
2 → 4, MadEvent's σ reads 0.1–0.2 % low because it combines VEGAS iterations
with weights mean²/variance (`dsample.f:1995-1997`); see
[madevent-iteration-weighting-bias](../../../validation/madevent-iteration-weighting-bias.md).
Re-combining this row's *banked* survey with equal weights reads +0.68 %
above the reported value. That is one run and suggestive only, but it is
most of this row's +1.04 %. MadEvent's unweighted samples also under-populate
high-weight regions, by −5.4 % in that tail. So run first, before step 1:
- **Paired iteration test on this row.** On ≥10 fresh MadEvent directories,
  take per seed the equal-weight sum of the per-channel iteration values
  (`G*/results.dat`) minus the reported σ, inclusive and in the two
  radiative-return `pt(γ)` windows. The scripts are `iter_seed.py` and
  `combine.py` under the scratchpad's `2to4-work/`, and the archived
  results files are in `2to4-work/runs-results.tgz`.
- Any MadEvent number taken from an event fraction rather than a sliced σ is
  suspect. Say which of the row's existing numbers are of that kind.

If the paired test closes the offset, steps 1–2 shrink to confirming it per
window.
