## Scope

1. **Driver.** One entry point (a pixi task, e.g. `bank-seeded-sigma`, with
   `ROWS=`, `SEEDS=`, `SEEDS_4X=`, `NB_CORE=`) that, for each named manifest
   row:
   - generates the row's process directory once through its existing path
     (`build.sh`'s script, or the row's existing generator for
     `ee_to_mumua`, the MLM rows and `uu_tt`), with the same patches and
     cards as today;
   - copies it into a fresh never-run directory per seed, sets `iseed` (and
     `nevents` × 4 for the 4× seeds), and runs it with
     `madevent_seeds.sh`'s helpers;
   - keeps `results.dat`, every `G*/results.dat` and the banner per run;
   - computes per seed the reported σ ± error and the equal-weight sum of each
     channel's iterations (the logic of the sibling scripts `iter_seed.py` and
     `combine.py` under the scratchpad's `2to4-work/`; reimplement it in the
     repo, tested);
   - writes one per-row seed record into the refdata layout;
   - reports the screen: the 4× runs' distance from the 1× mean, in σ.
   It must retry a failed compile once (`madevent-seed-drivers-drop-failed-compiles`
   on PR #22's branch names the make race) and run `generate_events` from a
   scratch cwd.
2. **Bundle record.** A per-seed schema beside `sigma_reference.json`
   (reported, error, equal-weight value, budget, seed, wall time,
   `validated_ew: bool` per row, default false), with
   `assemble_bundle.sh`/`fetch_refdata.sh` carrying it.
3. **Gate reader.** `validate_sigma`/`validate_hadronic` read a row's seed
   record when present: the seed policy's unweighted mean with
   max(quoted, spread/√n), on the equal-weight values only where
   `validated_ew`, otherwise on the reported values. Absent a record, the
   current single value is read unchanged. **Inert:** with no new records
   banked, every gate reads exactly what it reads now (byte-identical
   report).
4. **A dry run here** on two cheap rows (one fixed-beam 2 → 2, one hadronic),
   with 2 seeds at reduced `nevents`, written to a scratch refdata copy
   (never committed), showing the record and the gate reading it.

Do not bank anything, and do not commit refdata. `helas/` is off limits.

- **First action**: `cd` to the absolute worktree path in your assignment, then

  find yourself in the shared main checkout, STOP and report — never edit it.
  Re-verify `pwd` after any resume; resume is when isolation leaks.
- **Background anything expected to exceed ~2 minutes**
  (`run_in_background: true`, output redirected to a log file prefixed with your
  worktree/session name — parallel siblings share one scratchpad and have
  clobbered each other's unprefixed logs). A backgrounded command notifies on
  exit: never spawn sleep-based watcher shells (they compound into
  self-sustaining wake-up rings); draft your notes and report between completion
  notifications instead of idle-waiting. On resume after a stall, first check

  re-running it.

  data; spot-check with `git log` / `git diff --stat` instead.

  reference data must be regenerated — without the reference data present, a
