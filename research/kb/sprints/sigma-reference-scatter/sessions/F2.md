## Scope

1. **`hard_survey = 2` on every banked run.** The driver sets it in each
   run's installed card (the committed cards stay untouched), and the seed
   record states it.
2. **Record the effective survey.** Per run, store `min_events`/`max_events`
   from `Source/run_config.inc` in the seed record. The screen output flags
   any row where they show `hard_survey` was inert (the
   `mmjj > 0.01·(ebeam1+ebeam2)` case).
3. **The heavy-tail flag.** Per row, compute each channel's (`G*`) seed
   χ²/dof across the 1× seeds. Record the worst, and flag the row when it
   exceeds 3. The flag only reports; the cell's `info`/`gate` mode stays a
   manifest decision for the manager and the user.
4. **Fail bad runs.** A run fails, and is retried once in a fresh copy as
   now, when it writes fewer events than `nevents`, or when its σ is not a
   finite positive number. `generate_events` exits 0 on the `libgammaUPC.a`
   compile race, so the exit code is not enough.
5. **Inert:** with no records present, `validate` reads exactly what it does
   now.
6. **A dry run** on `ee_to_mumu` and `pp_to_bb_fixed` (5 + 2 seeds, reduced
   `nevents`), showing `hard_survey = 2` in the banner and `run_config.inc`,
   the recorded min/max, and the per-channel χ²/dof. Add one forced failure:
   a fake short event file must be refused.

`helas/` is off limits. Do not bank anything or commit refdata.
