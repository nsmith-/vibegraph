## What was built

**Driver.** `validation/madgraph/bank_seeded_sigma.sh` is run as the pixi task
`bank-seeded-sigma` in the `madgraph` environment. It takes `ROWS` (rows or
groups, required), `SEEDS` (default 20261101–20261105), `SEEDS_4X` (default
20261111 20261112), `NB_CORE` (default 2) and `JOBS` (rows at once, default 1).
The diagnostic overrides are `NEVENTS`, `VALIDATED_EW_ROWS`, `SEEDED_OUT` and
`SEEDED_WORK`. Per row, the driver:

1. Generates a template process directory once and never runs it. It reuses
   the row's existing path:
   - `script` rows: `build.sh`'s new `script_driver`, with the launch block
     dropped and models staged by `stage_models`. The run card and param card
     are the banked `output/<row>/Cards/`. The launch block's `set` lines are
     checked against that card by `mes_check_card`, minus `iseed` and
     `nevents`.
   - `mlm` rows: the same script, on the committed `<row>_run_card.dat`.
   - `dy13` rows: `generate p p > e+ e-` on `dy13_*_run_card.dat`.
   - `onshell` (`uu_tt`): `gen_onshell_veto.sh`'s process, card and overrides,
     generated by the p1d-patched tree (`mes_p1d_tree`).
   - `pta` (`ee_to_mumua`): delegated to `gen_pta_windows.sh --stage
     mll-371`. The five windows run in their own fresh directories, and the
     seed's value is their sum.
2. For each seed, copies the template fresh and installs the card with `iseed`
   set, plus `nevents` × 4 for `SEEDS_4X`. It runs `mes_run_seed`, which now
   starts `generate_events` from a scratch cwd. A failure is retried once in a
   new copy.
3. Keeps the run under `output/seeded_sigma/<row>/s<iseed>/` and then drops the
   run directory. The kept files are `SubProcesses/results.dat`, every
   `P*/symfact.dat` and each `G*/results.dat` it lists, `banner.txt`,
   `init.txt` (the event file's `<init>` block) and `vg_seed_result.txt`. A seed
   already kept under a byte-identical card is read back (`VG_FORCE=1`
   re-runs it).
4. Runs `seed-record`, a new binary in `validation-report`, which writes
   `output/seeded_sigma/<row>/seed_record.json` and prints the screen. At the
   end the driver collects each row's `SCREEN` line into `work/seeded_sigma/screen.txt`.

**Record and reading rule.** `vibegraph-lib/tests/common/seed_record.rs` holds
both, and the writer includes it by path.
- Schema 1. Per row: `budget_nevents`, `validated_ew` (default false), the MG
  version and tree, and the generator text.
- Per seed: `iseed` and `nevents` (both read from the banner), the reported
  value ± error, the equal-weight value ± error, wall time, the channel count,
  the iteration range, and `by_lprup` for rows with several `@N` processes.
  Partitioned seeds also list their windows.
- Equal weight is, per channel listed in `symfact.dat`, the unweighted mean of
  its iterations, summed over channels. The error is √Σeᵢ²/n per channel, in
  quadrature.
- The writer refuses a run whose channels do not sum to MadEvent's
  `results.dat` total within 2e-4 relative. This tests the claim that the kept
  channels are the ones MadEvent combined; a test pins it on a real 3.7.1 run
  whose channel 2 is split into `2.1`/`2.2` and which has a `Hel` directory.
- Reading: the seeds at the budget only, under `combine` (unweighted mean,
  max(quoted, spread/√n)), on equal weight only where `validated_ew` is set.
  Fewer than 5 seeds at the budget panics (the policy floor). The 4× seeds are
  the screen and are never averaged in.
- Screen: each 4× seed's pull, and the 4× mean's pull, against the 1× mean.
  The row is flagged when |pull| > 2.

**Gate reader.**
- `validate_sigma`: `sigma_gate_matches_madgraph` and the long-tier driver
  pass each row through `BankedSigma::madevent_reference`. The cell note names
  the record when one was read.
- The grammar gate reads a record for its three restricted rows
  (`ee_to_mumu_zonly`, `ee_to_ee_nsz`, `ee_to_wp0wm`). Their controls stay on
  `grammar_sigma_reference.json`.
- `validate_hadronic`: `banked_llj_sigma` (every single-run hadronic gate),
  `banked` (the two dy13 references, rows `dy13_default` and
  `dy13_mmll_60_120`) and `seeded_reference` (the MLM rows, total and per `@N`)
  all prefer a record.
- A record that exists but is malformed panics; it does not fall back.
- Absent a record, every path returns exactly what it returned before (see
  the gate below).

**Bundle.** `assemble_bundle.sh` now selects `seeded_sigma/<row>/seed_record.json`
and `seeded_sigma/<row>/s<digits>/**`, so a partial `s<iseed>.tmp` keep is never
carried. `fetch_refdata.sh` needed no change: it unpacks the whole archive into
`output/`.

**Refactors for reuse:**
- `build.sh` is sourceable. Its body is `build_main` and runs only when the file
  is executed.
- `check_card` (from `gen_mlm_references.sh`) and `p1d_tree` (from
  `gen_onshell_veto.sh`) moved into `madevent_seeds.sh`. Both callers now use
  the shared versions.
- `gen_pta_windows.sh` takes `PTA_WORK`/`RESULT_JSON`, so the driver's runs
  leave `output/` and the committed `pta_window_reference.json` alone. It also
  runs `generate_events` from a scratch cwd.

**Scope addition (`bd92c97`).** `time_stages.py --nb-core N` sets
`run_mode = 2`, `nb_core = N`:
- Script rows: through `set … --no_save` lines. The launch applies the
  session's MadEvent options from its history (`launch_ext_program.MELauncher`).
- dy13 rows: through `me5_configuration.txt`, as `mes_configure_dir` does.

Each entry records `nb_core` (null without the flag) and `results_dat`. Each
run's `SubProcesses/results.dat` (with `<cumulated_time>`) is copied to
`<out>/results/<process>.results.dat`. Without the flag the behaviour is
unchanged; the two new keys are added to the entry.

## Choices the brief and D1 left open

- **Where the driver lives.** It sits beside the other generators, and the
  record writer is a Rust binary rather than Python. That makes the
  recombination, schema and reading rule one implementation, tested in the
  hermetic layer, where Python is not available.
- **Where the record lives.** It is in the bundle at
  `output/seeded_sigma/<row>/`, not committed beside `sigma_reference.json`.
  D1 puts the per-seed record in the bundle, and refdata is not committed.
- **Screen statistic.** The 4× seeds' own seed-policy mean against the 1×
  mean, |pull| > 2. The per-seed pulls are printed as well.
- **D1's "widened to the measured budget shift"** is not implemented. The
  amendment replaces it with the screen, and two 4× seeds cannot calibrate a
  shift.
- **`validated_ew`** is set at bank time (`VALIDATED_EW_ROWS`) and lives in the
  record. Flipping it later means re-writing the record and re-assembling the
  bundle.

## Brief and comment errors

- **`pp_to_ll` is not a single-run row at iseed 21.** Its σ gate
  (`check_dy_run`) reads `hadronic_sigma_reference.json`'s `default` and
  `mmll_60_120`. Those are the `dy13_default` and `dy13_mmll_60_120` runs of
  `gen_hadronic_sigma.sh`, at iseed 33 on committed cards. `output/pp_to_ll`
  feeds only the αs and scale replays. The driver banks the two dy13 rows in
  its place, so `@hadronic` has 10 rows.
- **The comment's group counts are wrong.** The manifest has 30 fixed-beam
  2 → 2 σ rows, not 33. With the other groups that makes the 54
  (30 + 5 + 2 + 9 + 3 + 2 + 1 + 2).
- **`uu_tt`** is not among the 54. No `validate_sigma`/`validate_hadronic`
  gate reads it (its reference is `onshell_veto_reference.json`, read by the
  CLI on-shell-veto test). The driver supports it by name, but nothing reads
  its record.
- **Three rows are read by the grammar gate.** `ee_to_mumu_zonly`,
  `ee_to_ee_nsz` and `ee_to_wp0wm` are `Plan::Skip` in the main σ gate, and
  their cells come from the grammar gate. The reader is wired there, for the
  restricted entry only.
- **"Beside `sigma_reference.json`"**: the record is in the bundle, as above.
  `fetch_refdata.sh` needed no change.
- **Dry run "2 seeds"**: run with 5 + 2, as above.

## Found

- **`cli_integrate.rs` reads the dy13 references directly** from
  `hadronic_sigma_reference.json` (`banked`, line 51). A dy13 seed record
  would not reach it. To close it, include `seed_record.rs` by path there, as
  the CLI tests already include `seeds.rs`.
- **The pta generator only runs on the bank host.** `gen_pta_windows.sh`
  compares its template's `configs.inc` with `output/ee_to_mumua/SubProcesses/*/configs.inc`.
  The bundle does not carry that file, so the `@ee-mumua` banking (and any
  other run of that script) works only on a full MadGraph work area such as
  the M3, not on a fetched checkout. To close it, bundle `configs.inc` or
  compare against `configs.json`.
- **Hadronic cells do not name the record.** `validate_hadronic`'s σ cells
  (single-run, dy13 and MLM) do not record in their note that the MadGraph side
  came from a record: only stderr says so. `validate_sigma`'s cells do. To
  close it, pass the record's description into each hadronic cell's note.
- **`report.md` can never be byte-identical across runs**, because it prints
  durations. An inertness claim has to compare `report.json` and the cell
  files without timing fields, as done here.
- **Budget for `ee_to_mumua`.** The driver's budget is 100000 events per
  window (from the comment), so the record's 1× seeds are 100k-event window
  sums. The sigma gate then reads the window-sum mean in place of
  `sigma_reference.json`'s 10k-event single run. That is D1/#26's intent, but
  the manifest note on that row will need rewriting when it is banked.
